## 4. 测试中发现并修复的真实问题

本次不仅跑通了脚本，更在真机 Claude CLI 与真机浏览器测试中捕获并根治了 5 个实际工程问题：

1. **Claude Code CLI `2.1.325` 控制握手阻塞（90s 超时）**
   - **现象**：首次以 `--permission-prompt-tool stdio --input-format stream-json --output-format stream-json` 启动真实 `claude` 进程后，直接发送 `user` 帧不会产生响应，直至超时。
   - **根因**：新版本 Claude Code CLI 在启用 `stdio` 控制通道时，要求宿主先发送 `{ type: 'control_request', request: { subtype: 'initialize' } }` 并等待 `control_response(subtype: 'success')` 后才会消费首条 `user` 消息。
   - **修复**：在 `packages/core/src/runtime/claude-driver.ts` 中补齐初始化控制握手及未支持控制请求的兜底响应，真机两轮对话随即 100% 跑通。
2. **Windows 非 Git 工作区触发 `C:\.git` 与 `$Recycle.Bin` 权限错误**
   - **现象**：浏览器测试在 `C:\Windows\Temp` 下自动创建的 Agent 私有工作区切换 Changes 页签时，`git status` 向上追溯命中了 `C:\` 根目录残留的 `.git`，并因扫描 `$Recycle.Bin` 报权限错误。
   - **修复**：在 `packages/core/src/workspace/git-service.ts` 增加 `--show-toplevel` 盘符根目录保护（若仓库根为盘符根如 `C:\` 且工作区不在其明确注册边界内，则视为非 Git 目录安全降级返回空状态）+ 异常兜底，同时在 `packages/web/src/components/WorkspaceDock.tsx` 补齐 `try/catch`。
3. **1280px 视口下对话顶栏元素拥挤换行**
   - **现象**：浏览器实测在 1280px 宽屏同时打开左侧导航与右侧 Workspace Dock 时，`ChatView` 顶栏按钮存在轻微挤压。
   - **修复**：调整 `packages/web/src/components/ChatView.tsx` 顶栏 Flex 收缩与 `min-w-0` / `shrink-0` 约束。
4. **pnpm 11 预编译原生依赖安装策略变更**
   - **现象**：pnpm 11 忽略了旧字段 `onlyBuiltDependencies`，导致 `node-pty` 与 `esbuild` 构建脚本被跳过。
   - **修复**：在 `pnpm-workspace.yaml` 切换为 pnpm 11 规范的 `allowBuilds`，顺利释放 `node-pty@1.1.0` 预编译 Windows ConPTY 二进制。
5. **ConPTY 冷启动时序导致的偶发测试抖动**
   - **现象**：`e2e.test.ts` 中原本用固定 `800ms` 等待 PowerShell 回显标记，在冷启动偏慢时偶发超时。
   - **修复**：改为订阅 `core1.terminals.subscribe` 事件流，收到终端标记后再触发 `core` 热重启验证，消除时序抖动。

## 5. 快速启动与人工验收指南

### 5.1 一键启动服务（生产模式）

```bash
pnpm start
```

- 默认监听：`http://127.0.0.1:3210`
- 默认登录账号：`admin` / `admin`（建议登录后在 **Settings** 中修改密码）
- 开发热更新模式：`pnpm dev`

### 5.2 复跑全部自动化测试

```bash
# 1. 构建 + 全量 TypeScript 类型检查
pnpm build

# 2. 单元 + E2E + 扩展功能验收（4 文件 / 8 用例）
pnpm test

# 3. 生产启动健康冒烟
node scripts/smoke.mjs

# 4. 真机 Claude Code CLI 两轮实测（需本机已登录 claude CLI）
node --import tsx scripts/verify-claude-live.mjs
```

### 5.3 推荐的人工体验路径

1. 运行 `pnpm start`，浏览器打开 `http://127.0.0.1:3210`，用 `admin / admin` 登录。
2. 进入 **Settings** 页面，查看 **Environment Check** 确认 `git` 与 `claude` 状态为绿灯；如需使用内置轻量 Agent，在此添加任意 OpenAI 兼容 Provider（Base URL + API Key + Model）。
3. 进入 **Workspaces** 注册你的本地项目目录（或直接使用每个 Agent 自带的私有持久化工作区）。
4. 进入 **Agents** 创建一个 **Claude Code CLI** Agent（或 **Built-in Agent**），点击进入对话。
5. 在对话页发送代码阅读/修改任务，同时点击右上角展开 **Workspace Dock**，实时查看文件树编辑、Git Changes Diff 以及内置 Web 终端。

## 6. 已知限制与下一阶段规划（`v0.1b` / `v0.1c`）

按照既定范围约定，以下能力在 v2.0 架构与数据库/协议层已预留接口与表结构，尚未在 `v0.1a` 启用，将在后续版本迭代落地：

- **`v0.1b`（环境隔离与自由协作群）**：
  - 激活 5 层 Agent 环境隔离（私有 `CLAUDE_CONFIG_DIR`、`spawnPipeClean` 环境变量净化、只读凭据映射、Lockdown 模式）。
  - 启用多 Agent 自由协作群（`open-channel`）、`@mention` 路由、强制 `--disallowedTools Agent,Task` 禁止私开 Subagent，以及抗重启 MCP 桥。
- **`v0.1c`（圆桌会议、收件箱与多 CLI 扩展）**：
  - 启用 Pregel Super-step 节拍的圆桌会议策略（`roundtable`）与状态归约器（Reducer）。
  - 接入 Unified Inbox / Webhook / Cron 触发源，以及 Codex / Gemini CLI 等其他外部 Agent 驱动。
- **前端打包体积优化（非阻塞提示）**：
  - 当前 Vite 构建包含 `@xterm/xterm` 等依赖，单主包约 `749 kB`（gzip 后 `212 kB`），后续可通过路由级懒加载与 `manualChunks` 拆分优化首屏体积。
