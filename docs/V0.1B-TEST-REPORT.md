## 4. 测试中发现并根治的真实工程问题

1. **Web 前端 `ChatView.tsx` React #310 Hooks 调用顺序崩溃（真机浏览器捕获）**
   - **现象**：在未选中会话状态下新建「开放协作群」后页面立即白屏崩溃，控制台抛出 `Minified React error #310`。
   - **根因**：`packages/web/src/components/ChatView.tsx` 将 `useEffect(() => { setReplyTarget(null) }, [roomId])` 误写在 `if (!currentRoom) return ...` 提前返回之后。
   - **修复**：将 `useEffect` 移至所有提前 `return` 之前；修复重建后经浏览器真机建群、协作交互与强刷页面验证 0 报错。
2. **`AgentEnvironmentIsolator` 无条件设置 `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST=1` 导致 `isolated-home` 认证失败（真实 Claude CLI 捕获）**
   - **现象**：以 `isolated-home` 启动真实 `claude 2.1.325` 时，即使隔离 `CLAUDE_CONFIG_DIR/settings.json` 中已配置认证信息，CLI 仍立即退出报错 `Not logged in · Please run /login`。
   - **根因**：`packages/core/src/runtime/environment-isolator.ts` 对所有非 `standard` 模式无条件注入 `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST=1`，导致 Claude CLI 跳过读取隔离目录下的 `settings.json`；而按 `02-ARCHITECTURE.md` 设计，该开关仅应在宿主显式绑定自定义 `providerId` 并接管凭据时启用。
   - **修复**：将 `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST=1` 与 provider 覆盖变量归零收口在 `if (ctx.agent.providerId)` 内，同时保留 `cleanEnv` 与 `CLAUDE_CONFIG_DIR` 隔离；同步完善 `environment-isolator.test.ts` 并通过真实 Claude CLI 验证。
3. **`paused` 房间状态被普通消息/工具回写覆盖（多 Agent E2E 捕获）**
   - **现象**：调用 `rooms.control(pause)` 暂停房间后发送 `@Coder ...`，节点未维持 `queued` 而是直接被调度执行并完成。
   - **根因**：`packages/core/src/collab/collab-engine.ts` 中的 `applyActionsTx`（`set_room_state`）、`reassign`、`deliverWorkDeliveryTx`、`collab_dispatch`、`collab_reply` 直接 `UPDATE rooms SET state = 'running'`，未保护 `state != 'paused'`。
   - **修复**：为 `applyActionsTx` 增加 `allowUnpause` 参数（仅 `controlRoom` 传 `true`），并在上述非人工控制路径统一增加 `AND state != 'paused'` 守卫。
4. **中文无空格 `@mention` 分词边界过严**
   - **现象**：`parseLeadingMentions` 对所有昵称都要求后随空格或标点，导致 `@代码审查请评审一下` 等中文连写无法命中。
   - **修复**：在 `packages/core/src/collab/open-channel-strategy.ts` 中区分 ASCII 单词后缀边界校验与 CJK/非 ASCII 结尾最长前缀直配。
5. **其他构建与测试修复**
   - `packages/protocol/src/collab.ts`：`CollabStrategy.configSchema` 改用 `z.ZodType<TConfig, z.ZodTypeDef, unknown>` 兼容 Zod `.default(...)`；
   - `packages/web/src/components/WorkspaceDock.tsx`：显式导入 `ReactElement` 兼容 React 19 TypeScript 配置；
   - `packages/core/src/workspace/worktree.test.ts`：为包含多次真实 `git` 子进程调用的用例补充 `20_000ms` 超时；
   - `packages/core/src/collab/open-channel.test.ts`：由于 `context-builder.ts` 会在每条系统提示词中附带完整成员花名册，将 Mock LLM 角色匹配改为精确匹配 `You are seated as **@${name}**` 并修正多轮上下文断言。

## 5. 快速启动与人工验收指南

```bash
# 1. 启动生产服务（http://127.0.0.1:3210，默认账号 admin / admin）
pnpm start

# 2. 全量构建与自动化回归
pnpm build && pnpm test && node scripts/smoke.mjs

# 3. 真实 Claude 2.1.325 二进制 + isolated-home + MCP 桥全闭环测试（离线本地 Anthropic SSE 桩）
node --import tsx scripts/verify-claude-v01b-live.mjs --mock-anthropic

#    如需连接本机真实登录的 Claude 上游运行 open-channel 协作实测（需上游网络畅通）：
node --import tsx scripts/verify-claude-v01b-live.mjs
```

### 建议人工体验路径
1. 打开 `http://127.0.0.1:3210` 登录后，在「**智能体**」页面创建多个内置或 Claude Agent，可分别体验 `standard` / `isolated-home` / `lockdown` 环境隔离标签。
2. 在「**工作区**」页面登记一个本地 Git 仓库目录（可直接点击「新建 Worktree / 清理 Worktree」验证 `RepoMutex` 隔离）。
3. 点击左上角 `+`，切换到「**开放协作群 (多 Agent)**」，勾选至少 2 名 Agent 并指定一位 **主责 Lead**、绑定 Git 项目目录创建群聊。
4. 在群内尝试使用 `@everyone` / `@成员`、引流提问（消息悬停「回复」）、委派子任务到 `worktree`，并点击右侧工作台「**任务**」页签查看层级任务树、改派成员及跨轮共享记忆。
