## 4. 测试中发现并解决的工程问题

1. **`ChatView.tsx` 圆桌「转交执行」触发 `room_members` 唯一索引冲突（真机浏览器捕获）**
   - **现象**：当圆桌中担任 `Chair` 的成员不是房间第 0 个成员时，点击 `转交执行` 提交转交返回 `UNIQUE constraint failed: room_members.room_id`。
   - **根因**：SQLite `idx_room_single_lead` 索引约束每个未移除房间最多只能有 1 个 `role_kind = 'lead'`；而原前端映射逻辑使用 `m.roleKind === 'chair' || idx === 0`，当 `idx === 0`（如 `Auditor`）与非零位置的 `Chair`（如 `Lead`）同时满足条件时会产生两个 `'lead'`。
   - **修复**：在 [ChatView.tsx](../packages/web/src/components/ChatView.tsx) 中先唯一定位 `leadMember`（优先取 `chair` 或 `lead`，兜底取首名成员），再按 `m.id === leadMember.id` 唯一分配 `'lead'`（同时 `single` 模式转交也对齐选取 `leadMember`）；重建并通过浏览器全流程复测。
2. **Fastify `/webhooks/generic/:hookId` 补充支持标准 `Authorization: Bearer` 头**
   - **修复**：在 [http-server.ts](../packages/core/src/transport/http-server.ts) 保留 `X-Webhook-Secret` 与 `?secret=` 的同时增加 `Authorization: Bearer <secret>` 解析，并在 [inbox.test.ts](../packages/core/src/inbox/inbox.test.ts) 中同时覆盖。
3. **测试辅助细节对齐**
   - `githubWebhookPlugin` 的 `externalKey` 规范格式为 `${event}:${repo}:${number}:${action}`（如 `issues:acme/core:42:opened`），同步对齐 `inbox.test.ts` 断言；
   - `BuiltinDriver` 会在系统提示词顶部附加基础角色身份句，在 [roundtable.test.ts](../packages/core/src/collab/roundtable.test.ts) 中针对 `# Collaboration Room:` 协作段精确验证匿名掩码，并断言 3 个独立席位全部参与第 2 轮互评。
4. **已知表单设计备注（非阻塞）**
   - 当前 Web 前端 `InboxView` 的「自动路由规则」创建表单未内置工作区下拉选择框（目标工作区在规则 API 中为可选字段，手动指派工单时可在弹窗内按需指定工作区）。
